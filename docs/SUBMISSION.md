## Состав

1. Код с историей, README, архитектурной схемой и сценарием проверки.
2. `compose.submission.yaml`: один запуск лёгкого локального комплекта, отдельные volumes/порты; не заменяет существующий стенд.
3. `compose.product.yaml` и `docs/PRODUCT_RUNBOOK.md`: PostgreSQL/Redis/RQ/Qdrant и эксплуатационная основа, место доверенной идентификации.
4. Python/Node версии, `backend/requirements.lock`, `frontend/package-lock.json`, образы с digest.
5. `THIRD_PARTY_NOTICES.md`, перечни Python/frontend компонентов.
6. Генератор двух вымышленных компаний/ФЛ/платежей и `test_cases/submission_scenarios.json`. Тестовый пользователь не требуется для localhost. Живые карточки не предзагружаются.
7. `alpha-submission-materials.tar.gz`: 9 настоящих PDF кейса + соответствующие OCR sidecars и манифест SHA-256. Скачивание на странице GitHub Release для допущенных экспертов. Контрольная сумма архива — `docs/materials-archive.json`.
8. `docs/COMPLIANCE.md`: критерии, реализованные механизмы и ограничения. OpenAPI доступен в работающем API.

## Установка материалов

Скачайте архив из Release в корень checkout, проверьте SHA-256 и распакуйте:

```sh
shasum -a 256 alpha-submission-materials.tar.gz
tar -xzf alpha-submission-materials.tar.gz
cp .env.submission.example .env.submission
# Заполните только локальный .env.submission ключом организаторов.
docker compose -f compose.submission.yaml up --build -d
```

Адрес: http://127.0.0.1:28080 . Если архива нет, скопируйте предоставленные организаторами PDF в `data_alfbnk/`; OCR нужно выполнить явно перед анализом. В индекс попадают только sidecars с совпадающим SHA-256. Нельзя считать анализ банка проверенным без его материалов.

Для повторного OCR собственных материалов после сборки, с явным writable-каталогом:

```sh
docker compose -f compose.submission.yaml run --rm -v "$PWD/data_alfbnk:/ocr" prepare python -c "from agent.rag.index_documents import index; index('/ocr')"
docker compose -f compose.submission.yaml restart backend worker
```

## Выполненные проверки

- Локальные unit/component/API: **53 теста прошли**, включая реальный приватный CSV-loader. В контейнере без приватных CSV ожидаемо пропускается только этот тест.
- Контейнерная сборка Python 3.12 + Node 24/TypeScript/Vite: выполнена. Конфигурации submission/product/local Compose прошли проверку.
- Чистый изолированный запуск submission: prepare, Redis, backend, worker, frontend; API/worker/Redis healthy. Профили и форма новой новости проверены через браузер. Ошибка упаковки совместимых root-импортов обнаружена контейнерными тестами и исправлена.
- Реальный RSS-прогон: несколько сотен загруженных записей (точные числа и ошибки источников — в JSON соответствующего прогона), а не обещание обработать все статьи моделями.
- Живые отрицательные примеры: аккредитация СМИ и рейтинг Франции не дали опубликованных карточек для тестовых клиентов. Эти результаты не выдаются за успешный положительный сценарий. В старом статусе нулевая публикация называлась `failed`; исправлено: штатный отсев без ошибок даёт `completed`, audit/ошибки продолжают блокировать публикацию.
- Обнаружен настоящий сбой: Qwen тратил лимит на reasoning/пустой итог либо превышал timeout. Проба с `reasoning.effort=none` вернула структурированный ответ со ссылками на chunk ID примерно за 10 секунд. Настройка внесена в gateway-конфигурацию, unit-тест проверяет её фактическую отправку. Для DeepSeek/GLM задан `low`; успешность длинной цепочки подтверждена отдельным живым прогоном ниже.
- Retrieval на **настроечной**, не независимой выборке: 4 запроса / 3 отвечаемых и один запрос индивидуального договора. Recall@5 **1.0**, page precision **0.20**, no-answer accuracy **1.0**. Исправлены русские формы слов, добавлен BM25, разнообразие страниц и отказ от поиска индивидуального договора в публичных макроотчётах. Это не достаточный gate качества неизвестной выборки. Результат: `submission-retrieval.json`; прежний baseline сохранён отдельно.
- Ранее выполненные независимые технические проверки PostgreSQL/Redis/Qdrant, перезапуска, backup/restore и коротких API-проб зафиксированы в `PRODUCT_VERIFICATION.md`. Они не выдаются за новые массовые прогоны этой версии.

### Итог живых проверок

- `submission-live-e2e.json`: ранее не показанная текущая RSS-новость о премиях ESPO. Для U_14366 штатный отсев, для U_26030 score 0.88 и опубликованная карточка с валидным аудитом; живой чат вернул `fallback=false`, признал отсутствие условий договора; feedback действительно сохранён. Прямой банковский отчёт по нефти не подтверждён — это честно показано пользователю. Проверка выполнялась до последнего уточнения текста о ФТС и сокращения лимитов длинных задач; историческая карточка сохранена по постоянной ссылке.
- `submission-bank-e2e.json`: отдельный **известный** макроэкономический сценарий из кейса, на итоговой конфигурации. Для лизингового клиента использованы реальные страницы 1 отчётов `ALFA-Macro_Insights-Policy_Rate_11Sep.pdf` и `Бонд_Бриф_14092026.pdf`; банк/сводка ИИ разделены, независимый аудит разрешил публикацию. Это проверяет цепочку с банковской аналитикой, а не качество на неизвестной выборке.
- `submission-persistence.json`: реальный restart backend/worker, обе сохранённые карточки идентичны по digest; feedback count 1 сохранился. Доступ к исторической карточке работает независимо от текущей версии ленты; проверена изоляция этого маршрута по компании.
- `submission-model-usage.json`: сводка реальных вызовов, известных токенов и ошибок. Для локальной проверки израсходован весь резерв 200000 выходных токенов (это верхние резервы, не фактически сгенерированное количество). Новая чистая установка имеет собственный локальный счётчик; общий провайдерный ключ по-прежнему требует контроля бюджета команды. Лимит не сбрасывался ради успешного результата.

Сырые JSON прогонов — проверяемые свидетельства, не экспертные оценки полезности.

## Что не объявляется завершённым

- Нет независимой экспертной оценки качества на широкой отложенной выборке и банковской сертификации безопасности.
- Полноценное семантическое объединение разных публикаций в одно событие не заявлено; есть устранение точных дубликатов с сохранением источников и совмещение новости/профиля/аналитики банка.
- Денежный расход общего ключа и остаток 500 ₽ должны сверяться с провайдером; локальный output-budget не равен рублям или полному input+output.
- Hybrid BGE/vision, публичный банковский SSO/OIDC, нагрузочные SLO, расписание backup и реальная CRM не входят в подтверждённый комплект.
- Текущий сервер https://2.26.230.96 не обновлялся этой задачей. Локальная версия и Release имеют самостоятельный идентификатор.
