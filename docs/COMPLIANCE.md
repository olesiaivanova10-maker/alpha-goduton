# Проверка критериев и ограничений

Проверка 26.10.2026. Оценка опирается на код и явно перечисленные прогоны; техническая работоспособность не равна экспертному подтверждению качества. Ветка сдачи отличается от ранее опубликованного стенда.

| Критерий | Что есть / исправлено | Оценка |
|---|---|---|
| 1. Бизнес-контекст и релевантность | CSV-профиль: ОКВЭД, выручка, регион, продукты, ФТС; добавлены агрегаты платежей/связей и ограничения; Gemma оценивает конкретную пару клиент–новость | Реализовано; качество отбора требует независимой разметки |
| 2. Многофакторные последствия | Промпт и аудит ограничивают домыслы об остатке долга/валюте/ковенантах; вывод учитывает профиль и PDF; риски/возможности теперь показаны в карточке | Реализовано, глубина не гарантируется одной успешной генерацией |
| 3. Аналитика банка влияет на вывод | Реальные PDF/OCR → retrieval → Qwen → DeepSeek → аудит. В карточку добавлены исходные выдержки со страницами отдельно от сводки ИИ; дата неизвестна, если не установлена | Реализовано при наличии материалов; слабый retrieval остаётся ограничением |
| 4. Отбор/объединение/источники | RSS allowlist, хеши и группы возможных дубликатов, ранжирование, страницы/контрольные суммы, fail-closed аудит; похожие заголовки не считаются доказанным одним событием | Частично: полноценное кластерное объединение разных публикаций и независимая фактологическая оценка не доказаны |
| 5. Ранее не показанные новости | Добавлена форма произвольной новости; единая цепочка вместо подстановки экранов; негативные/неполные входы тестируются | Требуется экспертная проверка на отложенной выборке; 4 retrieval-запроса недостаточны |
| 6. Полный сценарий | Главная → клиент → запуск → статус → карточка с шестью вопросами → PDF/чат → оценка. Мнимая отправка менеджеру заменена копированием текста | Реализовано локально; публичный прод требует внешнего входа |
| Масштабирование и сопровождение | Раздельные HTTP/worker/scheduler, SQL/Redis, миграции, версии, очереди и runbook | Основа реализована; нагрузка/HA не сертифицированы |
| Метрики и feedback | SQL feedback, журнал по новости/компании/роли, usage моделей, измерения retrieval; процесс экспертной проверки описан в README | Реализовано для прототипа; автоматического переобучения нет |
| Точка входа на главной | Постоянная ссылка в шапке и кнопка главной страницы | Реализовано в макете Альфа-Бизнеса |
| Интерактивность и источники | Чат по сохранённой карточке, новые вопросы и прямые PDF-ссылки | Реализовано; ответ может сообщать о недостаточности данных |
| Агентная логика | Классификация → релевантность → инструмент PDF → синтез → независимый аудит, резервный аудит при сбое, отсев/отказ при недостаточности | Реализована ограниченная управляемая цепочка; свободного выполнения команд нет |
| Трассируемость | Этапы/причины, признаки, версии, источники, audit, usage и job | Реализовано без хранения скрытых рассуждений модели |

## Ограничения кейса

- Используются четыре разрешённых текстовых LLM через выданный API. Другие LLM/vision не включены. BGE — необязательный retrieval-энкодер; в сдаче используется лексический поиск.
- Общий лимит 500 ₽/день задаёт провайдер. В приложении есть ограничения вызовов/выходных токенов и usage, но **нет доказанного рублёвого ограничения общего ключа**, когда неизвестны тарифы/запросы других участников.
- Неполные признаки не доказывают отсутствие продукта; ФТС не доказывает валюту/экспорт, кредитный продукт — остаток или плавающую ставку. Предусмотрены предупреждения, условные выводы и блокировка невалидного аудита. OCR чисел требует сверки с PDF.
- Безопасная архитектура описана в README/runbook и частично проверена тестами изоляции. Проверочный Compose намеренно локальный и без входа. Для интернет-доступа обязательно HTTPS/вход и изоляция администратора.

## Итог

Решение имеет нужную архитектуру и интерактивный сценарий, комплект сдачи устранит воспроизводимость и видимые пропуски интерфейса. **Полного подтверждения всех шести критериев успеха пока нет:** остаются качество retrieval/персонализации на независимой неизвестной выборке и объединение нескольких публикаций в событие. Эти ограничения нельзя честно закрыть декларацией или фикстурными ответами моделей.
