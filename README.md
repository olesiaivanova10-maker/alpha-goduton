# AI Engineer & Prompt Architect Workspace

Рабочая папка со всеми файлами, относящимися к зоне ответственности **Prompt Engineer / AI Architect**:

```
ai_engineer/
├── prompts/                     # Все специализированные промпты под модели
│   ├── gemma_classifier.py      # Gemma 4 — бинарный классификатор (отсев спама)
│   ├── gemma_ranker.py          # Gemma 4 — скоринг релевантности (0.0 - 1.0)
│   ├── qwen_rag.py              # Qwen 3.6 — RAG-выжимка отчетов банка
│   ├── deepseek_insight.py      # DeepSeek-V4.1 — глубокая финансовая интерпретация (6 вопросов)
│   ├── qwen_chat.py             # Qwen 3.6 — интерактивный Q&A чат в веб-интерфейсе
│   └── glm_orchestrator.py      # GLM-5.3 — факт-чекинг, аудит галлюцинаций и оркестрация
├── models_cfg.py                # Конфиг утвержденной связки нейросетей команды
├── bank_knowledge_base.py       # Локальный RAG-ретривер со стеммингом (9 отчетов Альфа-Банка)
├── orchestrator.py              # Главный координатор сквозного пайплайна и сохранение отчетов
├── schemas.py                   # Pydantic-схемы данных (контракты JSON)
├── adapter.py                   # Мост-адаптер контекста компании из бэкенда в AI-модель
└── test_cases/
    ├── golden_dataset.json      # Эталонный датасет (3 кейса: металлургия, ритейл, агро)
    └── test_rag.py              # Автономный тест RAG-поиска (100% точность)
```

## Docker Compose

Docker Desktop должен быть запущен. Из корня проекта:

```bash
cp -n .env.example .env
docker compose up --build -d
docker compose ps
```

Интерфейс: http://localhost:8080. Swagger: http://localhost:8081/docs.
Ключи ALFA_HACK_API_KEY и ALFA_HACK_API_BASE задаются в .env и передаются только backend.
CSV поместите в backend/data/, PDF — в data_alfbnk/. Файлы монтируются только для чтения.
Feedback и отчёты хранятся в именованных volumes и переживают пересоздание контейнеров.

```bash
docker compose logs -f --tail=50
docker compose up -d --force-recreate backend  # после изменения .env
docker compose down  # остановка без удаления volumes
```

Порты можно изменить через FRONTEND_PORT и BACKEND_PORT в .env.
Live API не требуется для старта; наличие ключа само по себе не подключает live-генерацию к статической ленте.

## Проверка данных и моделей

`GET /health/models?force=true` выполняет реальные короткие вызовы четырёх моделей и кэширует результат. Ошибки авторизации возвращаются без секретов.
RSS snapshot хранится в `/app/storage/news.json`, сохраняется после пересоздания контейнера.

OCR PDF запускается отдельно на компьютере с Poppler, Tesseract и языками rus+eng:

```bash
python -m agent.rag.index_documents
```

Рядом с PDF создаются `.pages.json` с checksum и реальными страницами. Они доступны контейнеру через PDF volume. Retrieval пока лексический; BGE/vector поиск не реализован.
RAG передаёт извлечённые страницы в Qwen, если API доступен. Отсутствие источников не обозначается официальной позицией банка.
`/chat` использует Qwen только при найденном PDF-контексте; иначе возвращает сообщение о недоступности.
`/feed` возвращает только сохранённые персональные инсайты, прошедшие аудит. При отсутствии результатов лента пустая; статические карточки не подставляются.

## Живая лента

В интерфейсе выберите компанию и нажмите «Сформировать живую ленту». Обрабатываются до двух деловых RSS-новостей за один запрос. Карточки сохраняются отдельно для компании и роли, повторная обработка сохранённой карточки не вызывает модели заново.

- `POST /api/feed/refresh?company_id=U_26030&role=CFO&limit=2` — фоновая генерация, возвращает job_id.
- `GET /api/feed/jobs/{job_id}` — этап обработки и результат.
- `GET /api/feed?company_id=U_26030&role=CFO` — только проверенные сохранённые карточки.
- `GET /api/reports/files/{filename}` — исходный PDF, с защитой от выхода за каталог.

Новости, персональные карточки и feedback переживают пересоздание контейнеров через storage volume. Фоновые задачи текущего пилота выполняются в процессе backend; перезапуск прерывает незавершённую задачу. Для публичной эксплуатации необходим отдельный worker с восстановлением задач, авторизация и контроль доступа.

Аудит получает текущую дату, дату новости, полный профиль и исходные PDF-фрагменты. При недоступном или невалидном ответе GLM выполняется реальная резервная проверка Gemma. Если обе проверки не дали вердикт либо выявлены ошибки, карточка не публикуется.

Live-проверка: одна RSS-новость успешно проанализирована для U_14366 и U_26030; сформированы разные карточки и подтверждены PDF-страницы. Чат по первой карточке успешно ответил и указал на отсутствие данных о плавающей ставке. Векторный BGE-поиск пока не подключён: retrieval по реальным OCR-страницам остаётся лексическим.
